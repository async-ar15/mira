01 — Overview

Beyond a wrapper

MIRA is fundamentally different from standard GPT wrappers. It utilizes LangGraph to coordinate specialized agents, vector search for context, and robust cloud infrastructure for compliance and analytics.

Graph-Based Orchestration

A LangGraph state machine orchestrates parallel execution of Security, Quality, Testing, and Documentation agents using diverse Gemini models.

Human-In-The-Loop (HITL)

If the aggregator agent's confidence drops below 0.5, the review is routed to a human queue in Slack instead of auto-posting to GitHub.

Role-Based Security

JWT authentication gates the dashboard. Viewers can see metrics, reviewers can trigger actions, and admins can export full ZIP bundles.

Immutable Audit Trails

Every finding, cost metric, and HITL decision is stored in Tiger Cloud and shipped nightly to an AWS S3 bucket with Object Lock (7-year retention).

03 — Local Setup

Get up and running

MIRA runs locally using Docker Compose, spinning up the FastAPI web server, the ARQ Redis worker, and MinIO for local audit log testing.

  1. 01

    Clone and Configure

    Clone the repository and copy the environment template.

    Bash 
    git clone https://github.com/async-ar15/mira.git
cd mira
cp .env.example .env
  2. 02

    Set API Keys

    You will need a GitHub Fine-Grained Token, a Gemini API Key, and your Tiger Cloud database credentials.

    ⚠
    AWS Credentials: For local development, the Docker stack uses MinIO. You only need real AWS S3 credentials when deploying to Railway.
  3. 03

    Boot the Stack

    Start the web server, Redis, and the ARQ worker queue.

    Bash 
    docker compose -f docker-compose.dev.yml up -d
